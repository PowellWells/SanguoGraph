# SanguoGraph 数据许可证治理

状态：维护者已于 2026-08-14 批准 CC BY 4.0；Round 10 已将决定写入稳定版发布边界。

本文件说明项目中不同材料的权利边界、引入规则和稳定版发布门槛，不构成法律意见。
实际授权范围与署名方式以仓库根目录 `LICENSE-DATA` 为准。

## 1. 当前有效边界

| 材料 | 当前状态 | 可否由项目统一再许可 |
| --- | --- | --- |
| React、TypeScript、脚本及项目自有软件代码 | `LICENSE` 所列 MIT License | 可以，限项目有权授权的代码 |
| 项目整理的人物、关系、来源结构与原创编辑说明 | CC BY 4.0，限项目有权授权的部分 | 可以，须注明“三国人物关系谱 · SanguoGraph”并遵守 `LICENSE-DATA` |
| 古代史料短摘录、书名、卷篇和版本定位 | 保留来源与版本记录 | 不因收录而自动改用项目许可证 |
| 现代研究摘录、图片和其他可能受版权保护的内容 | 原权利人条款优先 | 未获明确授权不得批量复制或统一再许可 |
| 外部结构化候选与外部标识 | 仅作内部研究线索，不参与前端构建 | 不得作为项目正式数据统一再许可 |

历史事实本身与数据库的选择、编排、编辑说明可能涉及不同权利。项目只处理自己有权
处理的部分，不以“事实公开”为由覆盖具体版本、现代整理或第三方数据库的权利。

## 2. 新数据进入正式层的许可检查

任何新增或纠错在合并前必须同时满足：

1. 明确记录典籍、作者、卷篇、版本或现代研究书目信息；
2. 仅保留核验主张所需的短摘录，不复制大段现代出版物；
3. 第三方结构化数据只作发现线索，由编辑者回到独立史料重新核验；
4. 无法确认允许使用范围的材料停留在研究区，不进入构建或发布成品；
5. 正式关系仍需符合 `confirmed + verified` 和非结构化候选史料要求；
6. 提交者声明有权提供材料供项目核验，但提交本身不等于项目已取得再许可权。

## 3. 已批准的独立数据许可证

维护者明确选择 CC BY 4.0，并保存独立 `LICENSE-DATA` 与范围声明。

### 正式采用：CC BY 4.0

适合希望允许广泛再利用、同时要求注明 SanguoGraph 来源的方案。Creative Commons
说明 4.0 许可证可用于数据库相关的版权及适用的特殊数据库权；但项目只能许可自己
有权许可的选择、编排和原创内容，必须明确排除第三方材料与各自受限内容。

### 未采用：ODbL 1.0

适合希望衍生数据库继续以相同开放条件发布的方案。ODbL 对数据库设置署名与
Share-Alike，并区分数据库权利与其中独立内容的权利；采用后需要额外明确数据库内容
许可证及 Produced Work 的署名方式，履约成本高于 CC BY 4.0。

### 当前不采用：CC0

在全部来源权利、短摘录版本和第三方候选边界完成逐项复核前，不把项目数据描述为
CC0，也不作超出项目权利范围的放弃声明。

## 4. 稳定版发布门槛

Round 10 按以下门槛完成数据许可收口：

- 维护者已明确批准 CC BY 4.0；
- 已加入 `LICENSE-DATA`、指定署名文本与范围声明；
- README、关于页、页脚和发布说明统一显示数据许可证；
- 抽查正式数据来源与短摘录，确认第三方或内部候选没有被错误纳入授权范围；
- 保留软件 MIT 与数据 CC BY 4.0 的双重边界。
