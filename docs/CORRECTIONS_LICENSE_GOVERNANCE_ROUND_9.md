# Round 9：纠错机制与数据许可证治理

完成日期：2026-08-14

## 1. 结构化反馈机制

仓库新增两个 GitHub Issue Form：

- `01-data-correction.yml`：人物、关系、史料、身份消歧和页面展示纠错；
- `02-source-suggestion.yml`：正史正文、注引材料、其他古代史料、现代研究与文学来源建议。

两类表单都要求实体定位、当前主张、建议修改或来源用途、可复核出处和提交确认。
表单明确限制大段现代版权文本，并声明提交不会自动写入正式数据。

## 2. 前端入口

- 人物档案提供“报告数据问题”和“补充史料来源”；
- 关系档案提供同样入口，并预填关系实体 ID 与永久链接；
- 史料浏览器与图谱内史料目录可针对具体史料提交反馈；
- 关于项目页提供通用反馈入口、审校流程和许可证边界说明；
- GitHub 表单链接使用实体 ID、稳定 Deep Link 和标题进行预填。

反馈机制不增加后端、登录或在线编辑功能。用户离线浏览时仍可查看全部内容；反馈入口
仅在用户主动点击且联网后打开 GitHub。

## 3. 审校规则

Issue 只是候选线索。正式数据修改仍须经过：

1. 同名人物与实体 ID 核对；
2. 典籍、卷篇、版本和短摘录定位；
3. 支持证据与反对证据分类；
4. 正文、注引、其他古代史料、现代研究与文学分层；
5. 权利与允许使用范围复核；
6. 数据测试、覆盖回归、构建和离线发布校验。

## 4. 数据许可证治理结论

本轮建立 `docs/DATA_LICENSE_GOVERNANCE.md`，正式区分：

- MIT 软件代码；
- 尚未授予独立许可的项目整理数据；
- 保留各自来源权利的史料短摘录与现代材料；
- 只用于内部研究、不进入构建的第三方结构化候选。

推荐维护者在 Round 10 前批准 CC BY 4.0；若需要衍生数据库强制保持开放，可改选
ODbL 1.0。当前不采用 CC0。维护者未作明确选择前，页脚继续显示“数据许可待定”，
项目不得宣称正式数据已经按开放数据许可证发布。

## 5. 数据边界

本轮不修改人物、关系或史料记录。冻结指标仍为 580 人、358 条正式关系、189 条史料，
其中 374 人入网、206 人孤立。
