235 条，有关系人物增至 257 人，孤立人物降至 280 人，覆盖率由 34.8% 提高至 47.9%。

## 2. 可重复审计

运行摘要与回归校验：

```powershell
npm run audit:relations
npm run validate:relation-coverage
```

生成按优先队列和展示阵营分组的当前 280 人清单：

```powershell
npm run audit:relations -- --list
```

机器可读结果：

```powershell
npm run audit:relations -- --json
```

`config/relation_coverage.json` 固定当前非回归基线；它不把现状定义为完成标准。
新增人物或关系时，不得通过删除人物改善覆盖率，也不得让有关系人物数或覆盖率倒退。

## 3. 补录顺序

### P0：既有家庭扩展批次异常缺口

第一、三、四、五批理论上都应接入家庭关系。目前此队列为 0；后续一旦出现，视为
数据回归并优先修复。

### P1：第二批主要人物

本队列启动时有 120 人。三批现已全部审核：魏系、吴系、蜀系与其他共使 46 名主要
人物接入图谱，当前仍有 74 人孤立。这 74 人继续保留在复核队列；“本轮未新增”只表示
当前名册与六类关系范围内未找到可安全闭合的证据。名字、同姓、同卷或共享展示阵营
都只能作为检索线索，不能直接生成关系。

### P2：第六批完整列传名册

主要人物三批审核完成后，下一阶段按《三国志》卷次处理当前 206 名第六批孤立人物。
优先检查与 P1 人物同传、附传或正文直接说明亲属身份的人物，以减少重复查证。

## 4. 第一阶段验收目标

- 将完全孤立人物从 350 人降至不超过 200 人，覆盖率提高至至少 62.7%；
- 先使用现有六类家庭关系，不因追求连通性补造政治、军事或事件边；
- 每条 `confirmed` 关系必须为 `verified`，并至少引用一条非结构化历史史料；
- 正文、裴注、其他古代史料、文学和程序候选继续分层表达；
- 关系研究队列中的“未发现”不等于“历史上没有”，只表示当前范围尚无可核验记录。

## 5. 后续模型决策

家庭关系扩展无法连接所有名臣武将。是否增加任职、政治、军事或事件关系，应作为
独立里程碑决定。若扩展，优先考虑人物—事件、人物—官职等带时间和史料的实体关系，
避免把共同参与同一事件的人物机械地两两相连。
