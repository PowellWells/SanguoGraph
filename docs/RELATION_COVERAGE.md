## 2. 可重复审计

运行摘要与回归校验：

```powershell
npm run audit:relations
npm run validate:relation-coverage
```

生成按优先队列和展示阵营分组的当前 244 人清单：

```powershell
npm run audit:relations -- --list
```

机器可读结果：

```powershell
npm run audit:relations -- --json
```

`config/relation_coverage.json` 固定当前非回归基线；它不把现状定义为完成标准。
新增人物或关系时，不得通过删除人物改善覆盖率，也不得让有关系人物数或覆盖率倒退。

## 3. 补录顺序

### P0：既有家庭扩展批次异常缺口

第一、三、四、五批理论上都应接入家庭关系。目前此队列为 0；后续一旦出现，视为
数据回归并优先修复。

### P1：第二批主要人物

本队列启动时有 120 人。三批现已全部审核：魏系、吴系、蜀系与其他共使 46 名主要
人物接入图谱，第二组又通过新补录亲属连接 3 人。二次复核进一步以 6 条既有节点间
的姻亲和宗族关系连接 7 名主要人物，当前仍有 64 人孤立。这 64 人继续保留在复核
队列；“本轮未新增”只表示
当前名册与六类关系范围内未找到可安全闭合的证据。名字、同姓、同卷或共享展示阵营
都只能作为检索线索，不能直接生成关系。

### P2：第六批完整列传名册

主要人物三批审核完成后，本阶段按《三国志》卷次处理第六批孤立人物。首轮利用卷二十
“武帝二十五男”和“文帝九男”两段正文，将 24 名宗室人物接入曹操或曹丕的父子谱系；
第二组又连接 2 人，主要人物二次复核再连接张温，当前剩余 179 人。后续继续优先检查
同传、附传或正文直接说明
亲属身份的人物。

### P3：第七批遗漏审计

首批补录 18 名卷二十诸王之母、卷三十五董厥和卷五十九孙虑。24 条母子关系均由
“某氏生某子”正文直接支持，孙虑以《吴主五子传》接入孙权父子谱系；董厥保持孤立，
不把任官、同僚或称许文字误建为亲属关系。后续遗漏补录继续使用批次 7。

第二组补录 20 名女性并新增 34 条关系；其中 27 条为正史正文直接记载，7 条为裴注
所引《魏略》《嵇氏谱》《吴录》材料，保持 `probable` 和 `pending_review`。夏侯氏
“产息女，为刘禅皇后”无法区分两位张皇后，因此没有猜测性建立母女边。

## 4. 第一阶段验收目标

- 将完全孤立人物从 350 人降至不超过 200 人；按当前 577 人总量，覆盖率至少 65.3%；
- 先使用现有六类家庭关系，不因追求连通性补造政治、军事或事件边；
- 每条 `confirmed` 关系必须为 `verified`，并至少引用一条非结构化历史史料；
- 正文、裴注、其他古代史料、文学和程序候选继续分层表达；
- 关系研究队列中的“未发现”不等于“历史上没有”，只表示当前范围尚无可核验记录。

### 指标防污染原则

- 关系收敛期以现有 577 人为优先，不再把扩大名册作为默认产出；
- 只有遗漏人物能够立即由合格史料接入正式关系网时，才评估是否补录；
- 不为达到 65.3% 把同姓、同卷、年代推断或常识性猜测提升为正式关系；
- 证据不足的线索只能保留在候选或待复核层，不能进入 `confirmed`；
- 家庭关系接近史料自然上限时，如实记录上限并启动模型决策，不修改验收口径掩盖结果。

## 5. 后续执行节奏：3 + 2 + 1

1. Round 1：第二批主要人物二次复核，已完成，净连接 8 名现有人物；
2. Round 2：卷 1—30 的既有孤立人物复核；
3. Round 3：卷 31—50 复核，完成后暂停并重新评估单位新增；
4. Round 4：若家庭关系仍有明显增量则复核卷 51—65，否则记录自然上限；
5. Round 5：全局遗漏、身份、来源和证据审计；
6. Round 6：数据冻结、桌面与移动端验收、离线发布验收。

Round 3 后不得因增量下降而降低证据标准。人物—事件、人物—官职等非家庭关系必须作为
独立语义图层另立里程碑，不能混入当前 324 条正式家庭关系。

## 6. 后续模型决策

家庭关系扩展无法连接所有名臣武将。是否增加任职、政治、军事或事件关系，应作为
独立里程碑决定。若扩展，优先考虑人物—事件、人物—官职等带时间和史料的实体关系，
避免把共同参与同一事件的人物机械地两两相连。
