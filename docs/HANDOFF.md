## 1. 项目当前状态

SanguoGraph 是一个以可定位史料为依据的三国人物关系知识图谱。目前没有
后端、数据库、登录或 AI API，正式图谱和离线单文件均由 React、TypeScript、
Vite 与 Cytoscape.js 构建。

当前正式层：

- 200 个人物；
- 33 条亲属、婚姻、收养或宗族／姻亲关系；
- 66 条历史文献来源；
- 默认显示曹操及其直接关系，共 18 人、27 条关系、9 条相关史料；
- “查看完整关系网”显示全部 200 人、33 条关系；
- 支持按视觉阵营浏览魏 70 人、蜀 45 人、吴 53 人、其他 32 人；
- 支持搜索、筛选、人物与关系档案、史料列表、节点探索和双人物最短路径；
- 新增人物未增加关系线：没有可靠亲属边的人物可以独立显示。
- 人物使用 `importBatch` 记录录入批次：原 24 人为第一批，新增 176 人为第二批。

当前只读候选层：

- 99 个 Wikidata 候选人物；
- 738 条未核验候选关系；
- 候选默认隐藏、按需加载，不在 CI 中重新下载；
- `data/processed` 的四个文件由哈希和 JSON Schema 保护。

当前可直接双击使用的离线入口：

```text

```

## 4. 视觉阵营约定

“魏、蜀、吴、其他”是图谱展示分类，不要求严格等同于人物生前已经建立的正式
政权。视觉阵营与正式史料字段 `Person.factions` 分开维护。

当前视觉阵营共计：魏 70、蜀 45、吴 53、其他 32。`Person.visualFaction`
是明确的展示字段，必须继续与正式史料字段 `Person.factions` 分开维护。
曹腾、曹嵩仍显示为其他；原核心家庭的其余 13 人仍显示为魏，不可根据卒年
自动改回“东汉／其他”。

当前视觉规则：

- 魏蓝、蜀红、吴绿、其他灰；
- 男性深色、女性浅色；
- 已核验且有正式史料的人物使用实线框；
- 待核验、虚构或缺少正式史料的人物使用虚线框；
- `recorded + confirmed + verified` 的关系使用实线；
- probable、disputed 和 candidate 等关系使用虚线；
- 配偶、宗族与姻亲是无向连线；
- 父母和收养关系保留方向。

实现位置：

## 5. 布局与交互现状

人物地图已改为确定性的家庭分支放射布局，继续使用 Cytoscape `preset`，没有
引入新的布局依赖。布局与视口服务位于：

```text
src/services/graphLayout.ts
src/services/graphLayout.test.ts
src/services/graphViewport.ts
src/services/graphViewport.test.ts
```

当前布局会：

- 以曹操为默认稳定锚点，祖先位于上方扇区、配偶与子女家庭单元位于下方扇区、
  同代宗族分支向左右交替展开，后代沿所属家庭扇区继续向外递归；
- 只用正式关系计算位置和代际；生物学父母优先决定家庭归属，收养关系在已有
  生物学父母时作为跨支线关系，候选边不影响正式层布局；
- 按后代叶节点数量分配分支角度，桌面最小节点中心距离为 112px，紧凑视图为
  104px，核心节点再增加 12px；
- 通过二维空间哈希处理碰撞，严格保留用户锁定坐标，其他节点沿原分支射线向外
  避让；断开的分量沿主分量外围螺旋排布；
- 输出 `bounds` 和按关系 ID 索引的 `edgeRoutes`；家庭主干优先使用直线，
  收养、宗族、跨家庭及并行关系使用确定性曲线，并避开无关节点的扩展碰撞圆；
- 相同输入产生完全相同的位置和路由，120 人合成多分支图的测试也保持无重叠。

视口与标签交互：

- 首次加载先适应全图；如果缩放低于 `0.72`，改用可读缩放并居中曹操或当前
  选中人物；
- 图谱更新和窗口调整时保存 pan/zoom，不再反复自动缩小整图；搜索或展开人物
  仍会动画居中；
- “返回核心人物”回到曹操并使用可读缩放，“适应画布”仍明确显示整张地图；
- 关系标签默认使用智能模式：缩放低于 `0.85` 时仅保留选中、路径、悬停及选中
  人物直接关系的标签；工具栏“标”按钮可强制显示全部标签，使用
  `aria-pressed` 表达状态，触摸设备可点击关系查看标签。

首屏不会一次塞入 200 人。默认只显示曹操及其直接关系；搜索隐藏人物会把该
人物加入当前探索集，例如搜索“刘备”后为 19 人、27 条关系。用户也可从人物
档案选择“查看完整关系网”进入全部 200 人视图，或用阵营按钮直接查看魏、
蜀、吴、其他人物。阵营按钮只改变人物范围，不生成任何阵营关系线。

## 6. 史料与数据红线

- 不得编造原文、卷次、链接或现代学术观点；
- 外部结构化数据只能提供候选线索；
- Wikidata 不能单独支撑 `confirmed` 关系；
- 正式关系必须至少引用一条非 `structured_dataset` 来源；
- `certainty` 与 `reviewStatus` 必须继续分离；
- 正式 JSON 中不得写入 candidate 或 derived；
- 直接记录、间接推定、编辑者推断和候选关系必须可区分；
- 宗族边只表达引文直接支持的范围，不得自动补出中间谱系；
- `clan_relative_of` 是无向关系，反向重复边会被数据校验器拒绝；
- 无法可靠核验的关系宁可暂不进入默认图谱；
- 当前 33 条正式关系已经按用户要求冻结，未经新的明确授权不得增加；
- 没有正式关系的人物可以作为独立节点存在，不得为追求连通性补造关系；
- `data/processed` 是生成的只读候选层，不得手工编辑；
- 扩充人物前必须确认第三方数据的来源和许可证兼容性。

## 8. 后续工作建议

当前主要人物范围已经达到 200 人，下一步优先提升人物资料深度，而不是继续
快速扩大名单或关系数量：

1. 按阵营分批核对字、别名、简介和卷级来源，修正谨慎录入中的疏漏；
2. 在不增加关系线的前提下，补充可定位的原文摘录、译释或现代研究分层；
3. 改善 200 人完整地图和单阵营视图的筛选、分组与无关系节点导航；
4. 为人物名单增加重复名、别名冲突和卷次覆盖率等数据质量测试。

如未来确需恢复关系扩展，必须先取得用户明确授权，并建立新的关系范围与证据
验收标准；不能因为人物已经收录就推定他们之间存在正式关系。
